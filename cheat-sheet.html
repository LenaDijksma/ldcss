    Getting started

    Link two files and you are done.

    Install and link #

    Two files and a fonts folder, no build step needed to use it

    Build once with npm run build (or take the files from dist/), then link the stylesheet and the script. Keep the fonts/ folder next to the CSS: JetBrains Mono is self-hosted, so ldcss never calls Google Fonts.

    ldcss needs a current evergreen browser: it uses @layer, :has() and color-mix().

    <link rel="stylesheet" href="dist/ldcss.css">
<script src="dist/ldcss-theme.js"></script>   <!-- optional, tiny: no theme flash -->
<script src="dist/ldcss.js"></script>         <!-- end of <body> -->
    Class / attributeWhat it does
    dist/ldcss-theme.jsOptional, 0.3 KB, goes in <head> (blocking). Applies the theme a visitor chose earlier before the first paint, so there is no flash of the wrong theme. Without it everything still works; people who chose the opposite of their OS setting just see a brief flash.
    dist/ldcss.css, dist/ldcss.min.cssThe stylesheet. The .min file is the same rules with comments and whitespace removed.
    dist/ldcss.js, dist/ldcss.min.jsBehaviour for every data-ld-* component. Safe to load at the end of <body>; it also starts a mutation observer so markup added later is initialised.
    dist/fonts/JetBrains Mono (Latin subset, regular and bold, WOFF) with its OFL license. Must sit beside the CSS file.

    Naming conventions #

    Classes for structure, attributes for state and variants

    A class says what something is (ld-btn, ld-card). A data-ld-* attribute says which variant or state it is in (data-ld-variant="primary", data-ld-active="true"). Utilities are single-purpose classes, and any of them can be prefixed with a breakpoint, a theme or a state.

    Class / attributeWhat it does
    ld-*Component and utility classes: ld-btn, ld-pad-a-3, ld-grid.
    data-ld-*Variants, sizes, state and behaviour: data-ld-variant, data-ld-size, data-ld-active, data-ld-toggle.
    ld-{sm|md|lg|xl}:*Responsive utilities, from min-width 640 / 960 / 1200 / 1440px. Example: ld-md:d-flex.
    ld-dark:*, ld-light:*A small set of theme-specific utilities for one-off flips.
    ld-hover:*, ld-focus:*, ld-focus-visible:*State variants of common utilities. Example: ld-hover:bg-raised.
    --ld-*Design tokens (custom properties). Override them on :root or on any container.
    ld:{component}:{event}Bubbling CustomEvents. Listen with ldcss.on(); see the JavaScript page.

    Cascade layers #

    Why your own CSS always wins

    ldcss is split into six cascade layers, lowest priority first: ld.tokens, ld.base, ld.components, ld.utilities, ld.escape, ld.variants. A later layer beats an earlier one no matter how specific the selectors are, so a utility class always beats a component rule. CSS you write outside any layer beats all of ldcss, without !important.

    One consequence: a shadow utility such as ld-shadow-soft also wins over a button's :active shadow.

    /* your own stylesheet, unlayered: wins over every ldcss layer */
.ld-btn { border-radius: 0; }

/* or put your code in a layer of your own, declared after ld */
@layer ld, app;
@layer app { .ld-card { padding: 2rem; } }
    Class / attributeWhat it does
    @layer ld.tokens, ld.base, ld.components, ld.utilities, ld.escape, ld.variantsDeclared at the top of ldcss.css. Component rules live in ld.components, single-class utilities in ld.utilities, the per-element escape hatches in ld.escape, hover/focus variants in ld.variants.
    @layer ld, app;Put your layered CSS after ld to give it priority.

    Light, dark and unthemed #

    Set the theme with one attribute

    data-ld-theme on <html> (or any container) switches the palette. A toggle button remembers the choice in localStorage and falls back to the OS setting on a first visit. A light subtree inside a dark page works too.

    <html>                                  <!-- no attribute: follows the OS, no JavaScript needed -->
<html data-ld-theme="dark">             <!-- or choose one -->
<button data-ld-toggle="theme">Toggle theme</button>

ldcss.theme.get();          // 'light' | 'dark': what is showing now
ldcss.theme.set('dark');    // choose and remember
ldcss.theme.set('auto');    // forget the choice, follow the OS again
    Class / attributeWhat it does
    data-ld-themeValues: light · dark. On <html> or any container
    data-ld-unstyledResets radius/shadow/border-weight/accent-fill to neutral on a container, so your own stylesheet (loaded after ldcss.css) can restyle cleanly without fighting specificity — layout, spacing, and behavior are unaffected
    data-ld-nothemeFreezes subtree at light appearance
    data-ld-toggle="theme"Click to flip theme, persists via localStorage; on a first visit with nothing saved yet, falls back to the OS/browser's prefers-color-scheme
    data-ld-theme="light"Now also works on a subtree inside a dark page, using the same shared light tokens as :root and data-ld-notheme
    No data-ld-theme (automatic)With no attribute the page follows the operating system through prefers-color-scheme, from the very first paint and with JavaScript off. The build copies every [data-ld-theme="dark"] rule into a prefers-color-scheme: dark block, so the dark-only utilities and component tweaks follow too.
    dist/ldcss-theme.jsPut it in <head> to apply a saved choice before the first paint.
    ldcss.theme.get(), ldcss.theme.set("light" | "dark" | "auto")get returns what is showing; set chooses and remembers (in localStorage), "auto" forgets and follows the OS again. Fires ld:theme:change with { theme, setting }.
    color-schemeEach theme also sets color-scheme, so scrollbars and native controls match.

    Design tokens #

    Every colour, size and speed is a custom property

    Override a token on :root for the whole page, or on one element for just that subtree. Colour tokens change with the theme; scale tokens do not.

    /* a rounder, bluer page */
:root { --ld-radius: 16px; --ld-accent: #2563eb; --ld-accent-text: #fff; }
    TokenMeaning
    --ld-accent, --ld-accent-text, --ld-accent-fillBrand colour, text on top of it, and the fill used by primary buttons (can be a gradient).
    --ld-bg, --ld-surface, --ld-surface-raisedPage background, card/input surface, and a raised or hovered surface.
    --ld-text, --ld-text-mutedBody text and secondary text.
    --ld-border, --ld-border-soft, --ld-border-widthDecorative borders, hairline dividers, and the border thickness. They are intentionally faint; do not use them to mark the edge of a control.
    --ld-border-controlThe edge of a form control (input, select, switch, range track, tag input, dropzone). 3:1 or better against the page, surface and raised surface in both themes, which is what WCAG 1.4.11 asks for.
    --ld-focus-ring, --ld-focus-border, --ld-code-textColour of the focus outline; the border colour of a focused field (the accent darkened toward the focus colour so it reaches 3:1 on every surface); code text.
    --ld-danger, --ld-success, --ld-warning, --ld-info (+ -text)Status colours and the readable text colour for each.
    --ld-shadow, --ld-shadow-lg, --ld-shadow-soft, --ld-shadow-soft-lg, --ld-shadow-color, --ld-shadow-offsetElevation. The soft pair is what data-ld-shadow="soft" points at; colour and offset belong to data-ld-shadow="hard".
    --ld-radiusCorner radius for components.
    --ld-space-{1-6,8}Spacing scale: 4, 8, 12, 16, 24, 32, 48px. --ld-gutter is one step of it used for layout gaps.
    --ld-text-{xs…4xl}, --ld-weight-{normal,medium,bold}, --ld-leading-{tight,normal,relaxed}Type sizes, weights and line heights.
    --ld-font-sans, --ld-font-mono, --ld-font-familyFont stacks; --ld-font-family is what text actually uses.
    --ld-z-{dropdown,popover,tooltip,modal,offcanvas,toast,command}Stacking order of the overlay components.
    --ld-transitionDefault speed and easing (120ms ease) for hover and focus changes.
    --ld-sidebar-widthWidth of the ld-shell sidebar column (15rem).

    Containers, grids and stacks #

    Centre it, grid it, stack it

    ld-container centres content and steps its width per breakpoint. ld-grid is an even, responsive grid; ld-grid-row with ld-col-* is a 12-column grid for uneven layouts; ld-stack spaces children vertically.

  </div>
</div>

    Sidebar and app shell #

    A sidebar that becomes a menu on small screens

    ld-shell wraps an ld-sidebar and the content (ld-shell-main). From a breakpoint up the sidebar is a sticky column; below it, it becomes a sticky top bar with a dropdown menu. Pick the breakpoint with data-ld-collapse-at (default sm, 640px). See demo-sidebar.html for a full page, and this page for a real one.

    <div class="ld-shell" data-ld-collapse-at="md">
  <aside class="ld-sidebar">
    <div class="ld-sidebar-header">
      <a class="ld-nav-brand" href="/">Brand</a>
      <button class="ld-btn ld-sidebar-toggle" data-ld-toggle="navbar-collapse"
              data-ld-target="#side-menu" aria-expanded="false">Menu</button>
    </div>
    <nav class="ld-sidebar-body" id="side-menu" aria-label="Main">
      <ul class="ld-sidebar-links">
        <li><a class="ld-sidebar-link" href="#a" data-ld-active="true">Home</a></li>
      </ul>
    </nav>
  </aside>
  <main class="ld-shell-main">…</main>
</div>
    Class / attributeWhat it does
    ld-shell, ld-shell-mainThe grid that holds sidebar and content; ld-shell-main is the content column.
    data-ld-collapse-atOn ld-shell: sm (default) · md · lg · xl. The width at which the sidebar appears.
    ld-sidebar, ld-sidebar-header, ld-sidebar-toggle, ld-sidebar-bodySidebar frame. The toggle only shows below the breakpoint; the body becomes the dropdown there.
    ld-sidebar-links, ld-sidebar-link, ld-sidebar-heading, ld-sidebar-footerThe link list, one link (set data-ld-active="true" for the current one), a group heading, and a footer pinned to the bottom.
    --ld-sidebar-widthColumn width; override on ld-shell.
    BehaviourThe menu closes when a link is chosen and on Escape, which returns focus to the toggle. Works with data-ld-scrollspy.

    Resizable panels #

    Drag, or use the keyboard

    Mark a container data-ld-resizable; handles appear between its ld-panel children. Sizes are percentages, clamped by each panel's min and max, and can be remembered. Handles are keyboard operable: arrows move (Shift for bigger steps), Home and End jump to the limits, Enter collapses or restores, double-click resets.

    <div data-ld-resizable data-ld-persist="layout" style="height: 280px">
  <div class="ld-panel" data-ld-size="30" data-ld-min="15%">Files</div>
  <div class="ld-panel">Editor</div>
</div>

    Combobox #

    Static options, local items or a remote source

    One component, three data sources. With none set, it filters the options you wrote. With data-ld-source="#id" it fuzzy-matches a JSON <script>; with a URL it fetches results as you type. Focus stays in the input; the highlighted option is announced through aria-activedescendant, and result counts are read out politely.

    Typing again cancels the request still in flight, and an answer that arrives late for an old query is discarded, so the list never shows stale results. Answers are remembered per query (turn off with data-ld-cache="false").

    <div class="ld-form-group" data-ld-combobox
     data-ld-source="/api/people?q={q}" data-ld-debounce="250" data-ld-min-chars="2">
  <label class="ld-label" for="who">Person</label>
  <input class="ld-input" id="who" type="text">
  <div data-ld-combobox-list></div>
</div>

    Search bar #

    Fuzzy search as a dropdown or as a page filter

    data-ld-search styles the input like any other field and puts a search button next to it, so clicking the magnifier does what Enter does. Inside the field it adds a clear button that appears once there is text, a shortcut hint, and a key (like /) that focuses it. Combine it with the combobox for a dropdown of ranked results, or point it at content on the page to filter that content. This page's own search box is the first kind.

    Submitting (Enter or the button) fires ld:search:submit, makes sure the results are current and keeps focus in the field. With a result highlighted in an open dropdown, Enter still chooses that result. Inside a <form> the button is a real submit button.

    Matching is fuzzy and every word must match: btn pri finds both "Button" and "primary". Letters may skip, case and accents are ignored, and matches that start a word or sit together score higher.

</div>

<div data-ld-search data-ld-search-filter="#cards" data-ld-search-count="#count">
  <input placeholder="Filter cards…">
</div>
<span id="count"></span>
<div id="cards"><article data-ld-search-item>…</article></div>

    Fuzzy matching API #

    The matcher behind the search bar, usable on its own

    A subsequence matcher with scoring (the approach of fzy): every query character must appear in order. A match scores higher when it is consecutive, starts a word, or follows a separator, and gaps cost a little.

    ldcss.fuzzy.match('btn', 'Button')        // { score, indices: [0, 3, 5] }  or null
ldcss.fuzzy.search('btn pri', items, { keys: ['name', 'desc'], limit: 10 })
ldcss.fuzzy.highlight('Button', [0, 3, 5])  // '<mark>B</mark>ut<mark>t</mark>o<mark>n</mark>
    Class / attributeWhat it does
    ldcss.fuzzy.match(query, text)Returns { score, indices } (matched character positions) or null.
    ldcss.fuzzy.search(query, items, options)Ranks items best first. Items are strings or objects; options.keys lists fields (strings, dotted paths, functions, or { name, weight }), limit caps results, threshold drops weak ones. A multi-word query is an AND.     Toasts and the queue #

    Short messages that stack and wait their turn

    ldcss.toast() shows a toast. At most data-ld-toast-max (default 5) are visible; the rest wait in a queue and appear as others close. Hovering or focusing a toast pauses its timer, and so does switching to another tab. Showing a toast with an id that is already up updates it instead of stacking a copy. Danger toasts are announced immediately.

    When you do not pass a duration, a toast stays long enough to read: 5 seconds, plus 40 ms for every character beyond 60, plus 3 seconds when it has buttons, never more than 15 seconds. Set data-ld-toast-default-duration on <body> to use your own number (0 keeps toasts until dismissed).

const t = ldcss.toast({ id: 'upload', title: 'Uploading', message: '0%', duration: 0 });
t.update({ message: '60%' });
t.update({ message: 'Done', variant: 'success', duration: 2000 });

ldcss.toast({ message: 'Item removed', progress: true,
  actions: [{ label: 'Undo', onClick: () => restore() }] });

    Easy tables #

    One attribute for sorting, search, paging and selection

    Add data-ld-table to a table and headers become sort buttons that work from the keyboard and announce the new order.     JavaScript API & events

    Events #

    One naming scheme for every component

    Every event is a bubbling CustomEvent named ld:{component}:{event} whose detail says what changed. Events named before-… are cancelable: call preventDefault() to stop the action. ldcss.on() subscribes with optional delegation, once, and a wildcard that sees every event.

    ldcss.on('toast:show', (e, detail) => console.log(detail.id));
ldcss.on('table:select', (e, d) => console.log(d.count), { target: '#people' });
ldcss.once('modal:show', () => track('opened'));
ldcss.on('*', (e) => console.debug(e.type, e.detail));   // everything

const off = ldcss.on('combobox:select', handler);
off();                                                    // unsubscribe
    EventDetail
    ld:modal|offcanvas|dropdown|popover|command:show, :hideshow: { trigger }; hide: {}. Fired on the panel (or backdrop) and bubbles.
    ld:tab:show, ld:accordion:show, :hide, ld:carousel:show, ld:navbar:show, :hideComponent specific; see the component.
    ld:disclosure:before-show, :show, :before-hide, :hide{ trigger }; before- is cancelable.

    Initialisation and observer #

    Add markup whenever you like

    ldcss starts a MutationObserver on <body>, so components in markup added later (from fetch, innerHTML or a framework) work with no extra call. It pauses while it initialises, so what it builds itself can never cause a loop.

    <body data-ld-observe="false">      <!-- opt out for the whole page -->
<div data-ld-no-observe> … </div>   <!-- opt out for one subtree -->

ldcss.unobserve();  ldcss.observe();   // runtime switch
ldcss.refresh(someElement);            // manual init of one subtree
    Class / attributeWhat it does
    data-ld-observe="false"On <body>: do not watch the page for added markup.
    data-ld-no-observeOn any element: markup inside it is left alone.
    ldcss.observe(), ldcss.unobserve()Start or stop watching.
    ldcss.refresh(root?)Initialise components in root (default the whole document), including root itself.
    ldcss.destroy()Stops the mutation observer, entrance-animation observers and carousel autoplay timers. Call it before removing a large chunk of DOM; ldcss.observe() starts watching again.
    ldcss.debounce(fn, ms)The debounce helper ldcss uses internally.
    ldcss.versionThe version string.

    Audit #

    Find the common mistakes ldcss cannot fix

    ldcss.a11y.audit() checks the page (or a subtree) for the mistakes that cannot be fixed automatically and returns them as a list. It also prints a table to the console. It is a quick lint, not a full audit: automated tools find only a part of real accessibility problems.

ldcss.a11y.audit(document.querySelector('#form'));  // one subtree

    The build #

    No dependencies, Node 18+

    ldcss builds with one script and nothing to install. npm run build once, or npm run watch to rebuild on every change. Edit src/, never dist/.

    npm run build     # writes dist/
npm run watch     # rebuilds when src/ or build/ changes
    PathPurpose
    src/css/<layer>/sNN-name.cssOne file per section, one folder per cascade layer (tokens, base, components, utilities, escape, variants). Files join in name order.
    src/css/**/*.gen.mjsGenerated CSS: the sidebar breakpoints, sizing/flex/grid/transition utilities, hover/focus variants. They read the breakpoint table, so a breakpoint is defined once.
    src/css/head.css@font-face for the self-hosted font (outside the layers).
    src/js/theme-init.jsBecomes dist/ldcss-theme.js, the tiny <head> script that applies a saved theme before first paint.

    src/js/ldcss.jsThe core: shared helpers, the original components and the public API.
    src/js/modules/NN-name.jsOne file per newer component (fuzzy, disclosure, context menu, toasts, resizable, combobox, search, tables, accessibility). Inlined into the core in name order, so modules share its helpers.
